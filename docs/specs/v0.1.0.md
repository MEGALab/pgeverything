# PGEverything — Design Spec (v0.1.0)

> One PostgreSQL image with everything a developer needs to build a modern AI Foundry.

**Status:** Draft / planning
**Target date:** 2026-07-21
**Decisions locked:** PostgreSQL 16 · JSONB for documents · TimescaleDB Community included · internal/dev use.

---

## 1. Philosophy

One PostgreSQL 16 server, one port (5432), seven workloads — no sidecar databases, no
polyglot sprawl. Everything is a Postgres extension so it is all transactional, backed up
together, and queried with one SQL dialect. This is the "AI Foundry substrate": relational
app data, vector embeddings, time-series telemetry, graph relationships, event streams,
document blobs, and a Redis-style key-value cache in a single ACID store.

---

## 2. Capability → implementation

| # | Capability          | Extension / mechanism                                            | `shared_preload` |
|---|---------------------|-----------------------------------------------------------------|:----------------:|
| 1 | **SQL**             | Core PostgreSQL 16                                               | —                |
| 2 | **NoSQL / document**| Native **JSONB** + GIN (`jsonb_path_ops`)                       | —                |
| 3 | **Graph**           | **Apache AGE** (openCypher)                                     | ✅ `age`         |
| 4 | **Time-series**     | **TimescaleDB** Community (hypertables, continuous aggregates, compression) | ✅ `timescaledb` |
| 5 | **Pub/Sub**         | **pgmq** (durable queues) — primary; `LISTEN`/`NOTIFY` for ephemeral fan-out | — |
| 6 | **Vector**          | **pgvector** (HNSW/IVFFlat) + **pgvectorscale** (StreamingDiskANN) | —             |
| 7 | **Key-value cache** | **pgcache** (first-party: UNLOGGED table + JSONB values + `pg_cron` TTL sweep) | — |

**Bundled quality-of-life extensions** (cheap, high value for a foundry):
`pg_stat_statements`, `pg_trgm` (fuzzy text), `pg_cron` (scheduled SQL),
`uuid-ossp` / `pgcrypto`. **PostGIS** optional, gated by a runtime env flag
(`PGE_ENABLE_POSTGIS`) — its binaries already ship in the Timescale base, so enabling is
just a conditional `CREATE EXTENSION` at first boot, no rebuild needed.

```
shared_preload_libraries = 'timescaledb,age,pg_stat_statements,pg_cron'
```

(pgvector, pgvectorscale, pgmq, pg_trgm load via `CREATE EXTENSION`, no preload.)

---

## 3. Why PostgreSQL 16 (the binding constraint)

Apache AGE is the version limiter — it trails newest PG. PG 16 is the highest major where
**all six** ship working builds today (pgvector, TimescaleDB 2.17+, pgvectorscale, pgmq,
AGE 1.5.x). PG 17 would force dropping or self-patching AGE. Revisit to 17 once AGE 17
support stabilizes.

---

## 4. Build strategy

**Base:** `timescale/timescaledb-ha:pg16` — Timescale's HA image already bundles
TimescaleDB **+ pgvector + pgvectorscale + pgai** on PG16, saving three from-source builds.
Then layer the rest via a multi-stage Dockerfile.

- **Stage 1 (`builder`):** compile **Apache AGE** and **pgmq** from source against PG16
  headers (no reliable prebuilt binaries for this exact base).
- **Stage 2:** copy the built `.so`/SQL artifacts into the Timescale base, add init scripts
  and config.

```dockerfile
FROM timescale/timescaledb-ha:pg16 AS base

FROM base AS builder
  # apt: build-essential, postgresql-server-dev-16, bison, flex, git
  # git clone apache/age (release/PG16) → make && make install
  # git clone pgmq → make && make install

FROM base
  COPY --from=builder <age + pgmq artifacts>
  COPY rootfs/docker-entrypoint-initdb.d/*.sql /docker-entrypoint-initdb.d/
  COPY rootfs/postgresql.conf.d/pgeverything.conf ...
```

## 5. First-boot initialization

`/docker-entrypoint-initdb.d/00-extensions.sql` runs once on an empty data dir:

```sql
CREATE EXTENSION IF NOT EXISTS timescaledb;
CREATE EXTENSION IF NOT EXISTS vector;         -- pgvector
CREATE EXTENSION IF NOT EXISTS vectorscale;    -- pgvectorscale
CREATE EXTENSION IF NOT EXISTS age;            -- graph
CREATE EXTENSION IF NOT EXISTS pgmq;           -- durable queues
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS pg_cron;
CREATE EXTENSION IF NOT EXISTS pgcrypto;
LOAD 'age'; SET search_path = ag_catalog, "$user", public;
```

Plus a `10-smoke-demo.sql` that creates one object per capability (a hypertable, a vector
column, a graph, a queue) so a fresh container is immediately demoable.

**Optional PostGIS** — a `05-postgis.sh` init hook runs only when `PGE_ENABLE_POSTGIS` is
truthy, executing `CREATE EXTENSION IF NOT EXISTS postgis;` (binaries are already present in
the base image, so no rebuild is required):

```bash
# rootfs/docker-entrypoint-initdb.d/05-postgis.sh
if [ "${PGE_ENABLE_POSTGIS:-false}" = "true" ]; then
  psql -v ON_ERROR_STOP=1 --username "$POSTGRES_USER" --dbname "$POSTGRES_DB" \
    -c 'CREATE EXTENSION IF NOT EXISTS postgis;'
fi
```

## 6. Interfaces / ports

- **5432** — single Postgres endpoint for all seven workloads. No extra ports (JSONB-only
  means no FerretDB/MongoDB sidecar).
- Pub/Sub is in-band over the SQL connection. **pgmq** is the primary mechanism —
  durable, transactional queues with visibility timeouts, read-with-ack, archiving, and
  optional partitioned queues (via `pg_partman` + `pg_cron`) for high throughput. Native
  `LISTEN`/`NOTIFY` remains available for ephemeral, best-effort fan-out (cache
  invalidation, live UI pings).

---

## 7. Config knobs (env-driven, foundry defaults)

`POSTGRES_PASSWORD`, tuned `shared_buffers` / `work_mem`, `max_connections`,
`timescaledb.telemetry=off`, `cron.database_name`, and `PGE_ENABLE_POSTGIS` (default
`false`) to toggle PostGIS at first boot. Ship a `docker-compose.yml` with a named volume
for `PGDATA`.

## 8. Verification plan (one smoke test per capability)

1. **SQL** — `SELECT 1`
2. **JSONB** — insert doc, query with `@>` + GIN index
3. **Graph** — `CREATE GRAPH`, Cypher `MATCH`
4. **Time-series** — `create_hypertable`, insert, `time_bucket`
5. **Pub/Sub** — `pgmq.send` / `pgmq.read`; `NOTIFY` / `LISTEN`
6. **Vector** — HNSW index, `<->` nearest-neighbor
7. **Key-value cache** — `cache_set` / `cache_get`, TTL expiry returns NULL

Ship as `make smoke` running `psql` assertions against a throwaway container.

---

## 9. Risks / open items

- **AGE build against Timescale's HA base** is the main integration risk (custom PG build
  flags) — needs a real compile test; may need to match their PG build exactly.
- **Image size** — expect ~1–1.5 GB. PostGIS binaries are already in the Timescale base, so
  the runtime `PGE_ENABLE_POSTGIS` flag adds no image weight; it only controls whether the
  extension is created at first boot.
- **`shared_preload` ordering** — `timescaledb` must be listed; AGE is order-tolerant.
  Verify startup logs.
- **pgvectorscale + AGE** both touch planner hooks — low risk, worth a co-load test.
- **Naming** — `pgeverything` (image/repo), `pge` short tag, "PGEverything" display name.
